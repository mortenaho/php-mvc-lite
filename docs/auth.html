Authentication and authorization

Session login is built in, plus policies, roles, and Blade @can. Keep policies in app/Policies and map them in config/auth.php.

Demo accounts

After php lite migrate:

demo@lite.test / password     role: user
admin@lite.test / password    role: admin

Admins can edit any post. Regular users can only change their own.

Routes

GET  /login
POST /login
GET  /register
POST /register
POST /logout      (auth)
GET  /account     (auth)

Creating, editing, and deleting posts requires a logged-in user. The Post policy decides who may update or delete.

Protecting a route

use Lite\Middleware\Authenticate;
use Lite\Middleware\EnsureRole;
use Lite\Middleware\RedirectIfAuthenticated;

$router->group(['middleware' => Authenticate::class], function (Router $router): void {
    $router->get('/account', [AccountController::class, 'show']);
});

$router->group(['middleware' => [Authenticate::class, EnsureRole::class . ':admin']], function (Router $router): void {
    $router->get('/admin', [AdminController::class, 'index']);
});

EnsureRole:admin,editor allows any of the listed roles.

Policies

php lite make:policy PostPolicy

Register the class in config/auth.php:

'policies' => [
    App\Models\Post::class => App\Policies\PostPolicy::class,
],
final class PostPolicy
{
    public function before(?User $user, string $ability): ?bool
    {
        return $user?->isAdmin() ? true : null;
    }

    public function update(User $user, Post $post): bool
    {
        return (string) $user->id === (string) $post->user_id;
    }
}

Return null from before to fall through to the ability method. true allows, false denies.

In controllers and views

auth()->check();
auth()->hasRole('admin');
auth()->isAdmin();

$this->authorize('update', $post);
can('update', $post);
@can('update', $post)
    <a href="{{ url('/posts/' . $post->id . '/edit') }}">Edit</a>
@endcan

Pass a model instance for update/delete, or the class name for create: authorize('create', Post::class).

Custom abilities without a policy:

gate()->define('access-reports', fn ($user) => $user?->hasRole('admin'));

Roles

Users have a string role column. The User model uses Lite\Auth\HasRoles. role is not mass-assignable, so registration cannot create an admin.

$user->hasRole('admin');
$user->isAdmin();

Passwords are hashed with password_hash. Login regenerates the session id. CSRF is still required on POST.
